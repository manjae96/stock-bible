# 콘텐츠 작성·검토 가이드

## 반드시 지킬 것

1. **바뀌는 제도·세율·시간은 고정된 사실처럼 쓰지 않는다.** "검토일 기준", "확인 필요"를 붙이고 공식 출처(KRX, 국세청, SEC 등)를 안내한다. 세율 숫자는 넣지 않는다.
2. **한국과 미국이 다르면 `kr`, `us` 필드로 나눈다.** 화면은 사용자가 고른 시장에 맞춰 보여준다.
3. **확률·성공률 숫자를 쓰지 않는다.** 패턴의 `stats.status`는 실제 데이터로 계산하기 전까지 `unverified`. "흔히 ~라고 설명한다(검증 전)"처럼 쓴다.
4. **가상 데이터 결과를 실제 통계처럼 쓰지 않는다.**
5. **AI가 쓴 글은 `status: 'ai-draft'`.** 사람이 출처와 대조한 뒤에만 `reviewed`로 바꾼다.

## 용어 항목 체크리스트

- [ ] 한글명·영문명·약어
- [ ] 한 문장 정의 (`def`)
- [ ] 쉬운 설명 (`easy`)과 숫자 예시 (`ex`) — 계산이 맞는지 직접 확인
- [ ] 계산식과 단위 (`f`, `unit`) — 해당될 때
- [ ] 실제로 확인하는 방법 (`check`)
- [ ] 흔한 오해 (`myth`)와 해석의 한계 (`limit`)
- [ ] 관련 용어 (`rel`) — 존재하는 id만
- [ ] 퀴즈 (`q`) — 정답 번호 `a`는 0부터
- [ ] 출처 키 (`src`) — `meta.js`의 SOURCES에 있는 키
- [ ] 수준 `lv`, 시장 `mk`, 기간 `hz` 태그

## 패턴 항목 체크리스트

- [ ] 성공·실패 차트 (`charts.success`, `charts.failure`)의 anchors와 주석
- [ ] 형성 조건, 확인할 위치, 형성 중·확인됨의 차이
- [ ] 일반적인 해석과 필요한 조건, 거래량·추세·시장 환경 확인점
- [ ] 무효화 조건, 학습용 시나리오(진입·손절·목표·비중)
- [ ] 수준별 설명 1·2·3
- [ ] 통계 상태와 코드로 옮길 수 있는 판정 규칙 초안

## 검토 절차

1. 항목별로 출처를 열어 정의·숫자·제도를 대조한다.
2. 숫자 예시를 계산기로 다시 계산한다.
3. 틀린 부분을 고치고 `status: 'reviewed'`, `reviewedAt: 'YYYY-MM-DD'`로 바꾼다.
4. `meta.js`의 CHANGELOG에 "무엇을 왜 고쳤는지" 기록한다.
5. `node tools/validate-content.mjs` 실행.
